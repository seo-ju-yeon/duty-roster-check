# Duty Roster Check

가상의 간호사 근무표를 읽고 데이터 오류와 배정 규칙 위반을 검사하는 Python 프로젝트입니다.
작은 테스트 자료로 검사 기능을 구현한 뒤, 표 데이터 분석과 OR-Tools·LLM 생성 근무표 비교로 확장할 예정입니다.
모든 배정 규칙은 학습을 위해 정한 가상 기준이며, 실제 병원 규정이나 법적 기준이 아닙니다.

## 현재 진행 상황

2026-11-07 작업 폴더의 코드 기준입니다. 현재는 **1단계의 CSV 읽기와 입력 오류 검사**를 구현하고 있습니다.

| 작업 | 상태 |
| --- | --- |
| 작은 테스트 자료와 예상 결과 준비 | 작성됨. 설정상 자료 검토 상태는 `pending_user_review` |
| TOML 설정 읽기 | 검사 기간, 허용 근무 상태, 기준 간호사 인원수 사용 |
| 간호사 CSV 읽기·입력 검사 | 구현됨 |
| 근무표 CSV 읽기·입력 검사 | 구현됨. 아래 목록 참고 |
| 같은 간호사·날짜의 중복 기록 검사 | 구현됨 |
| 간호사·날짜 기록 누락 검사 | 미구현, 다음 작업 |
| 필요 인원·근무 불가 CSV 읽기·입력 검사 | 자료 준비, 기능 미구현 |
| 인원 부족·근무 불가·연속 근무·금지 전환 검사 | 자료 준비, 기능 미구현 |
| 결과 CSV 저장·예상 결과와 자동 비교 | 미구현 |
| 대표 데이터 12명 × 14일, pandas 분석 | 예정 |
| OR-Tools 생성·LLM 응답 파일 검사·비교 | 예정 |

현재 구현된 입력 검사는 다음과 같습니다.

| 대상 | 검사 내용 |
| --- | --- |
| 두 CSV 공통 | 헤더 존재, 필수 열, 중복 열 이름, 행별 열 개수, 필수값의 빈 문자열·공백 |
| 간호사 목록 | 중복 간호사 ID, 설정의 기준 인원수와 실제 인원수 일치 |
| 근무표 | D/E/N/O 허용값, 실제 존재하는 날짜, 정확한 `YYYY-MM-DD` 형식, 검사 기간 포함 여부 |
| 근무표와 간호사 목록 대조 | 기준 목록에 없는 간호사 ID |
| 근무표 전체 행 대조 | 같은 간호사·날짜 기록 중복. 근무 상태가 달라도 중복으로 판단 |
| 기간 설정 | 시작일이 종료일보다 늦은지 확인 |

현재 발견한 첫 입력 오류에서 `ValueError`로 실행을 중단합니다. 파일 경로가 잘못되면 `FileNotFoundError`가 발생합니다.
입력값을 자동으로 수정하지 않으며, 오류 전체 수집과 결과 상태·규칙 ID 출력은 아직 구현하지 않았습니다.
현재 실행이 끝났다는 사실만으로 배정 규칙까지 통과했다고 판단할 수는 없습니다.

## 코드와 처리 흐름

코드는 현재 `main.py`에 모여 있습니다.

| 위치 | 입력 | 처리와 출력 |
| --- | --- | --- |
| `read_nurses()` | 간호사 CSV 경로 | 구조·필수값·중복 ID를 검사하고, 각 행을 딕셔너리로 담은 리스트 반환 |
| `read_schedule()` | 근무표 경로, 허용 근무 상태, 검사 기간, 등록된 간호사 ID 집합 | 행별 입력을 검사한 뒤 간호사·날짜 중복을 확인하고 행 리스트 반환 |
| 실행 부분 (`if __name__ == "__main__":`) | 설정 파일과 두 CSV의 경로 | 설정 읽기 → 간호사 목록 읽기·인원수 확인 → 근무표 읽기 → 행 수와 첫 행 출력 |

근무표 날짜는 검사할 때 `date` 객체로 변환하며, 반환하는 행에는 원래 날짜 문자열을 유지합니다.
근무표의 중복 검사는 모든 행의 값과 간호사 참조 검사가 끝난 뒤 수행합니다.

## 데이터 구성

현재 자료는 `data/fixtures/small/` 아래에 있으며, 모두 UTF-8 CSV입니다.
각 파일의 첫 줄은 열 이름입니다. 아래 행 수는 헤더를 제외한 데이터 행 수입니다.

```text
duty-roster-check/
├── main.py
├── config.toml
├── README.md
├── docs/
│   └── rules.md
└── data/fixtures/small/
    ├── nurses.csv
    ├── requirements.csv
    ├── unavailability.csv
    ├── base/
    │   └── schedule.csv
    ├── input_cases/
    │   ├── nurses/       # 간호사 CSV의 구조·값·인원수 확인 자료
    │   └── schedule/     # 근무표 CSV의 구조·값 확인 자료
    ├── cases/            # 기본 근무표에서 독립적으로 만든 오류 사례
    ├── expected_issues.csv
    └── expected_summary.csv
```

### 기준 자료와 예상 결과

| 파일 | 한 행의 의미·존재 이유 | 행 수 | 현재 사용 여부 |
| --- | --- | --- | --- |
| `nurses.csv` | `nurse_id`로 식별하는 간호사 한 명. 유효한 ID와 인원수를 확인하는 기준 | 4 | 읽기·검사에 사용 |
| `base/schedule.csv` | `nurse_id,date,shift`로 표현한 간호사 한 명의 특정 날짜 상태. 정상 기준 후보이자 오류 사례의 출발점 | 12 | 읽기·입력 검사에 사용 |
| `requirements.csv` | `date,shift,min_staff`로 표현한 날짜·근무조별 최소 필요 인원 | 9 | 이후 인원 부족 검사에 사용 예정 |
| `unavailability.csv` | `nurse_id,date`로 표현한 근무할 수 없는 하루 | 1 | 이후 근무 불가 날짜 배정 검사에 사용 예정 |
| `expected_issues.csv` | 예상 오류 사건 하나의 규칙 ID, 위치, 실제 값, 기준, 이유 | 8 | 수동 대조용. 자동 비교 미구현 |
| `expected_summary.csv` | 기본 근무표와 오류 사례별 예상 행 수, 입력 상태, 위반 사건 수 | 8 | 수동 대조용. 자동 비교 미구현 |

작은 자료는 N01~N04의 **4명 × 3일 = 12행**입니다. D는 주간, E는 오후, N은 야간, O는 휴무입니다.
휴무도 O로 한 행을 기록하며, 행 자체가 없는 것은 배정 누락입니다.
대표 자료는 **12명 × 14일 = 168행**으로 계획하고 있으며, 아직 파일을 작성하지 않았습니다.

기본 근무표를 날짜별로 펼치면 다음과 같습니다.

| 간호사 | 2026-11-01 | 2026-11-02 | 2026-11-03 |
| --- | --- | --- | --- |
| N01 | D | D | O |
| N02 | O | O | D |
| N03 | N | N | O |
| N04 | O | E | N |

기본 근무표와 예상 결과는 검토 후 고정할 테스트 자료이며, 현재 설정의 검토 상태는 `pending_user_review`입니다.
`expected_issues.csv`와 `expected_summary.csv`는 검사기 구현 전에 정한 기대값입니다.
현재 프로그램이 생성한 결과가 아니며, 추후 실제 결과 파일로 덮어쓰지 않습니다.
이 두 예상 결과 파일의 범위는 기본 근무표와 `cases/`의 7개 사례입니다. `input_cases/`는 포함하지 않습니다.

### 간호사 입력 확인 자료

아래 파일은 `input_cases/nurses/`에 있습니다. `nurses_path`에 지정하며, 근무표 경로에는 지정하지 않습니다.

| 파일 | 만든 이유 | 기대 결과 |
| --- | --- | --- |
| `too_many_fields.csv` | 헤더는 1열인데 데이터에 값 2개를 입력 | `read_nurses()`에서 2번째 줄의 값 개수 초과 오류 |
| `too_few_fields.csv` | 헤더는 `nurse_id,memo`인데 데이터에는 N01만 입력 | `read_nurses()`에서 2번째 줄의 값 개수 부족 오류 |
| `empty_memo.csv` | `N01,`처럼 선택 열 `memo`의 자리만 남기고 값을 비움 | `read_nurses()` 통과. 전체 실행에서는 기준 4명 대비 실제 1명이므로 인원수 오류 |
| `empty_nurse_id.csv` | 필수값인 `nurse_id`를 비움 | `read_nurses()`에서 2번째 줄의 필수값 누락 오류 |
| `duplicate_nurse_id.csv` | N01을 두 번 기록 | `read_nurses()`에서 5번째 줄의 중복 ID 오류 |
| `too_few_nurses.csv` | 서로 다른 간호사 3명만 기록 | `read_nurses()` 통과 후 실행 부분에서 기준 4명과 인원수 불일치 오류 |

`empty_memo.csv`는 선택 열의 빈 값을 허용하는지 확인하는 **함수 단독 확인용 자료**입니다.
`too_few_fields.csv`의 `N01`과 `empty_memo.csv`의 `N01,`는 쉼표 유무가 다릅니다.
전자는 열 하나가 부족하고, 후자는 열 개수는 맞지만 선택값이 비어 있습니다.

### 근무표 입력 확인 자료

아래 파일은 `input_cases/schedule/`에 있습니다. 기준 간호사 목록을 사용하고 `schedule_path`에 지정합니다.

| 파일 | 만든 이유 | 기대 결과 |
| --- | --- | --- |
| `too_many_fields.csv` | 3열 헤더에 값 4개를 입력 | 2번째 줄의 값 개수 초과 오류 |
| `empty_shift.csv` | 필수값인 `shift`를 비움 | 2번째 줄의 `shift` 필수값 누락 오류 |
| `invalid_date.csv` | 존재하지 않는 날짜인 2026-11-31을 입력 | 2번째 줄의 날짜 오류 |

각 파일은 특정 입력 검사를 확인하기 위한 1행짜리 자료입니다. 완전한 12행 근무표로 사용하지 않습니다.

### 기본 근무표를 변경한 오류 사례

아래 파일은 `cases/`에 있습니다. 각 파일은 `base/schedule.csv`를 기준으로 독립적으로 변경했으며,
오류 사례끼리 변경 내용을 누적하지 않았습니다. `schedule_path`에 지정해 확인합니다.

| 파일 | 변경 내용 | 예상 오류·위반 | 해당 검사 구현 여부 |
| --- | --- | --- | --- |
| `unknown_nurse.csv` | 11월 1일 N02의 ID를 N99로 변경 | 기준 목록에 없는 N99 참조 1건 | 구현됨 |
| `duplicate.csv` | N01의 11월 1일 D 기록을 마지막에 추가 | 2번째·14번째 줄의 간호사·날짜 중복 1건 | 구현됨 |
| `missing.csv` | N01의 11월 3일 O 기록을 삭제 | N01의 해당 날짜 기록 누락 1건 | 미구현 |
| `understaffed.csv` | N03의 11월 1일 N을 O로 변경 | 해당 날짜 N 인원이 최소 1명에서 실제 0명으로 부족 1건 | 미구현 |
| `unavailable.csv` | N02의 11월 2일 O를 E로 변경 | 근무 불가 날짜 배정 1건 | 미구현 |
| `consecutive.csv` | N01의 11월 3일 O를 E로 변경 | D,D,E로 3일 연속 근무해 상한 2일 초과 1건 | 미구현 |
| `forbidden_transition.csv` | N03의 11월 2일 N을 D로 변경 | N→D 금지 전환 1건과 해당 날짜 N 인원 부족 1건, 총 2건 | 두 검사 모두 미구현 |

미등록 ID 사례는 참조 오류를 먼저 확인하므로 N02의 기록 누락까지 연쇄 집계하지 않는 기준입니다.
중복 1건은 중복된 간호사·날짜 조합 하나를 뜻하며, 관련 CSV 행은 2개입니다.
금지 전환 사례처럼 변경 하나가 여러 위반을 일으킬 수 있습니다. 예상 결과의 집계 단위는 **오류·위반 사건 수**입니다.

현재 미구현 검사의 사례를 실행해 읽기가 끝나더라도 해당 규칙을 통과했다는 의미는 아닙니다.
예상 결과의 `NOT_RUN`은 입력 오류 때문에 배정 검사를 수행하지 않는다는 뜻이며, 위반 0건과 구분합니다.
이 상태값을 프로그램에서 출력하는 기능은 아직 없습니다.

## 설정과 가상 규칙

기간·인원수·근무 상태·연속 근무 상한은 `config.toml`에서 관리합니다.
날짜·근무조별 최소 인원은 `requirements.csv`, 근무 불가 날짜는 `unavailability.csv`가 기준입니다.

| 항목 | 현재 작은 자료의 기준 | 코드 적용 상태 |
| --- | --- | --- |
| 기간 | 2026-11-01~2026-11-03, 양 끝 포함 | 적용됨 |
| 간호사 수 | 4명 | 적용됨 |
| 허용 근무 상태 | D / E / N / O | 적용됨 |
| 매일 최소 인원 | D 1명, E 0명, N 1명 | 검사 미구현 |
| 최대 연속 근무 | D/E/N을 근무일로 세어 최대 2일, O가 나오면 연속 종료 | 검사 미구현 |
| 금지 전환 | N 다음 달력 날짜의 D 금지 | 검사 미구현 |
| 근무 불가 | N02의 2026-11-02는 O만 허용 | 검사 미구현 |

`min_staff`는 최소 인원이며 초과 배정을 허용합니다. O는 필요 인원 검사 대상에서 제외합니다.
근무 불가 목록에 없는 간호사·날짜는 배정 가능하다고 가정합니다.
기간 밖 이력이 없으므로 경계를 넘어선 연속 근무와 근무 전환은 완전히 판단할 수 없습니다.

자세한 검사 의미와 향후 결과 형식은 [검사 기준](docs/rules.md)에 정리되어 있습니다.
해당 문서에는 오류 수집·결과 저장 등 예정된 동작도 포함되어 있습니다. 현재 구현 범위는 이 README의 진행 상황을 기준으로 확인합니다.

## 실행 및 수동 확인

Python 3.11 이상이 필요하며, 현재 확인한 버전은 **Python 3.11.9**입니다.
`csv`, `tomllib`, `pathlib`, `datetime` 표준 라이브러리만 사용하므로 현재 기능에 필요한 외부 패키지는 없습니다.

프로젝트 루트에서 프로젝트 가상환경으로 실행합니다.

```bash
.venv/bin/python main.py
```

### 기본 근무표 확인

`main.py` 실행 부분의 `nurses_path`와 `schedule_path`를 아래 값으로 지정합니다.
기존 경로 대입을 교체하고, 같은 변수를 뒤에서 다시 대입하는 줄이 활성화되어 있지 않은지 확인합니다.

```python
nurses_path = project_dir / "data/fixtures/small/nurses.csv"
schedule_path = project_dir / "data/fixtures/small/base/schedule.csv"
```

각 변수는 해당 파일을 읽는 함수 호출 전에 지정해야 합니다.
`nurses_path`는 `read_nurses()` 앞에, `schedule_path`는 `read_schedule()` 앞에 둡니다.

기본 근무표의 기대 출력은 다음과 같습니다.

```text
읽은 간호사 행 수: 4
첫 번째 간호사 행: {'nurse_id': 'N01'}
읽은 행 수: 12
첫 번째 행: {'nurse_id': 'N01', 'date': '2026-11-01', 'shift': 'D'}
```

이 출력은 현재 구현된 입력 검사를 통과해 행을 읽었다는 뜻입니다.

### 중복 오류 확인

기준 간호사 목록은 그대로 사용하고 근무표 경로를 변경합니다.

```python
schedule_path = project_dir / "data/fixtures/small/cases/duplicate.csv"
```

실행하면 간호사 목록 출력 뒤에 traceback과 다음 오류가 나타나야 합니다.

```text
ValueError: 입력 오류: 근무표 CSV 14번째 줄의 간호사·날짜 기록이 중복입니다: N01, 2026-11-01 (첫 기록: 2번째 줄)
```

**이 README 작성 시점의 코드에는 위 중복 오류 사례 경로가 활성화되어 있습니다.**
경로 변경 없이 실행하면 중복 오류가 발생하도록 설정된 상태입니다.
다른 사례도 해당 파일 경로를 지정한 뒤 표에 적힌 오류 종류와 위치를 대조합니다.
오류 확인 후에는 기본 근무표 경로로 복원합니다.

향후 사용하는 자료는 다음과 같이 구분합니다.

| 자료 | 목적과 확인 방법 |
| --- | --- |
| 검증용 고정 테스트 자료 | 검사기가 정해진 오류를 찾는지 확인. 실행 전에 정한 기대값과 비교 |
| OR-Tools 생성 근무표 | 제약조건을 표현해 생성한 결과가 규칙을 지키는지 확인하고 배정 분포 분석 |
| LLM 생성 응답 파일 | 테스트용 정답표·검사 결과를 제공하지 않은 별도 문맥에서 생성한 최초 응답의 형식과 규칙 준수 평가 |

LLM은 처음에는 외부에서 받은 응답 파일을 입력으로 사용합니다. 원본과 변환 파일을 구분하고,
형식 변환과 배정 수정, 도구 사용 여부를 기록할 예정입니다. 수정 결과는 최초 결과와 분리합니다.
검사기 검증용 오류 사례는 생성 방식 비교에 포함하지 않으며, 동일한 조건의 생성 결과끼리 비교합니다.
